## Чёткая формулировка задачи (переработка механизма drag в SvgEngine)

**Текущая проблема:**
- В `SvgEngine` фильтрация перетаскиваемых элементов идёт по жёстким CSS-селекторам (например, `.point-group`). Это связывает движок с конкретной предметной областью.
- Для добавления новых перетаскиваемых сущностей (например, подсвеченных рёбер) нужно расширять логику `SvgEngine`, что нарушает принцип открытости/закрытости.

**Требуемая архитектура:**
1. `SvgEngine` должен предоставлять **реестр колбэков** (массив функций), которые могут регистрировать сцены (PointsScene, EdgesScene).
2. Каждый колбэк принимает событие мыши (или DOM-элемент-цель) и возвращает:
   - **DOM-элемент**, который должен перетаскиваться (если событие произошло на подходящем объекте);
   - **null** (если объект не перетаскиваемый).
3. При старте drag `SvgEngine` последовательно вызывает все зарегистрированные колбэки. Первый колбэк, вернувший не-null, определяет перетаскиваемый элемент. Дальнейшие колбэки не вызываются.
4. Если ни один колбэк не вернул элемент, то drag не запускается (событие передаётся zoom/pan).

**Преимущества:**
- Сцены сами определяют, по каким признакам (класс, атрибут, данные) перехватывать drag.
- Нет жёсткой привязки к CSS-селекторам внутри `SvgEngine`.
- Легко добавлять новые перетаскиваемые объекты (например, подсвеченные рёбра) – достаточно зарегистрировать свой колбэк.

**Что нужно сделать:**
- Изменить `SvgEngine`: убрать `dragSelectors` и `dragPredicate`, ввести `registerDragDetector(callback)`.
- Переписать `PointsScene` и `EdgesScene` так, чтобы они регистрировали свои детекторы.
- Обеспечить правильный приоритет (точки важнее рёбер? обычно точка перекрывает ребро, но это решают сами колбэки порядком регистрации).

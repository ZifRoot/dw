# O(1) selection в `PointsScene`

## Цель

Состояние выбранной точки должно обслуживаться на уровне `PointsScene`, потому что selection — это состояние взаимодействия UI, а не состояние графа.

Главное требование: получение текущей выбранной точки в обработчиках сцены не должно выполнять поиск по массиву точек.

## Идея

В `PointsScene` хранится прямая ссылка на выбранную точку:

```ts
private selectedPoint: Point | null = null;
```

Вместо:

```ts
this.points.find((point) => point.selected)
```

сцена использует:

```ts
const previousPoint = this.selectedPoint;
```

Получение текущей selection становится O(1).

## Почему хранится Point, а не ID

`PointsScene` уже работает с объектами `Point`, а для обновления UI ей нужен сам объект.

Поэтому хранение:

```ts
Point | null
```

избавляет от дополнительного шага:

1. получить ID;
2. найти `Point` по ID.

Ссылка на объект уже является прямым O(1) доступом.

## Что происходит при клике

Обработчик `groupClick()` работает следующим образом.

### 1. Получаем текущую selection

```ts
const previousPoint = this.selectedPoint;
```

Это O(1).

### 2. Определяем точку под курсором

```ts
const point = this.dom2Point(domEle);
```

`domMap` используется для сопоставления DOM-элемента и точки, поэтому поиск точки не требует прохода по `this.points`.

### 3. Если выбрана другая точка

Если:

```ts
point && point !== previousPoint
```

то:

- старая точка снимается с selection;
- `selectedPoint` получает ссылку на новую точку;
- новая точка получает `selected = true`;
- обновляется UI старой точки;
- обновляется UI новой точки;
- через mediator отправляется новая выбранная точка.

Ключевой момент: чтобы узнать старую выбранную точку, **никакого `find()` нет**.

### 4. Если кликнули по уже выбранной точке

Текущая selection снимается:

```ts
this.setSelectedPoint(null);
```

После этого UI старой точки обновляется, а mediator получает `null`.

## Централизованное изменение selection

Изменение состояния выполняет один внутренний метод:

```ts
private setSelectedPoint(point: Point | null): void
```

Его ответственность:

1. не выполнять работу, если selection не изменилась;
2. снять `selected` со старой точки;
3. сохранить ссылку на новую точку;
4. установить `selected = true` новой точке.

Таким образом, `selectedPoint` и `Point.selected` изменяются вместе.

## Что происходит при PointChange

Если через mediator приходит изменение:

```ts
changes.selected === true
```

сцена передаёт найденную по ID точку в `setSelectedPoint()`.

Здесь используется уже существующий O(1) доступ `getPointById(pointId)`.

Если selection снимается с текущей точки, ссылка очищается.

Важно: PGM при этом не получает новую ответственность за selection.

## Инициализация

При создании `PointsScene` начальное состояние selection может быть восстановлено из массива точек:

```ts
this.selectedPoint = this.points.find((point) => point.selected) ?? null;
```

Это единственный начальный линейный поиск.

Он выполняется при создании сцены, а не при каждом клике или другом частом UI-событии.

После инициализации текущая выбранная точка доступна напрямую через `selectedPoint`.

## Почему не нужно добавлять selection в PointGraphManager

`PointGraphManager` отвечает за коллекцию точек и граф:

- хранение точек;
- получение точки по ID;
- добавление и удаление;
- связи графа;
- операции над графом.

Selection является состоянием визуального взаимодействия `PointsScene`.

Добавление в PGM отдельного:

```ts
selectedPointId
```

создаёт второе состояние, которое необходимо синхронизировать с:

```ts
Point.selected
```

Это усложняет архитектуру и переносит UI-ответственность в низкоуровневый компонент.

Поэтому selection остаётся в сцене.

## Сложность операций

| Операция | Сложность |
|---|---:|
| Получить текущую выбранную точку | O(1) |
| Получить точку по ID | O(1) |
| Получить DOM-элемент точки | O(1) через `domMap` |
| Сменить selection | O(1) |
| Снять selection | O(1) |
| Найти начальную selection при создании сцены | O(N), один раз |

Таким образом, критический путь клика по точке не содержит линейного поиска по коллекции.

## Главное архитектурное правило

> **Selection принадлежит сцене, а не графу.**

`PointsScene` знает, какая точка выбрана сейчас, и хранит прямую ссылку на неё.

`PointGraphManager` предоставляет O(1) доступ к точке по ID, но не знает ничего о визуальном selection.

Это позволяет получить O(1) обработку selection без добавления UI-состояния в низкоуровневый графовый менеджер.

## 4. Расхождения, обнаруженные исследователем

Этот блок предназначен для фиксации фактических несовпадений между Inventory и production/test code.

**Исследователь только фиксирует факт расхождения.** Он не обязан исправлять тест и не обязан составлять план исправления.

Project Manager использует этот блок как источник рабочих задач.

| Дата | Элемент | Тестовый файл | Что заявлено в Inventory | Что фактически проверяет тест | Что не совпадает | Ответственная роль | Статус |
|---|---|---|---|---|---|---|---|
| <date> | <element> | tests/unit/shared/... | Edge = [x] | Проверяется только success | Edge не проверяется | Project Manager | OPEN |
| | | | | | | | |

Статусы расхождения:

- OPEN — исследователь обнаружил расхождение;
- PLANNED — Project Manager включил исправление в план;
- IN PROGRESS — исполнитель исправляет тест;
- VERIFIED — исследователь подтвердил исправление;
- REPLAN — требуется новое экспертное решение.

## 5. Правила отметок

- [x] означает: соответствующий тест существует, проходит и проверяет именно эту категорию.
- [ ] означает: категория применима, но тест ещё не реализован.
- N/A означает: категория для элемента не применима.
- Нельзя ставить [x], если сценарий только рассмотрен или запланирован.
- Тест-файл должен указывать на реально существующий файл.
- VERIFIED означает, что исследователь проверил соответствие Inventory исходному коду и реальным тестам.
- Если исследователь обнаружил несоответствие, оно сначала фиксируется в блоке расхождений и не считается исправленным до повторной проверки.

## 8. Принцип работы с Inventory

Inventory является источником фактического состояния, а не списком задач для исполнителя.

Не нужно расширять Inventory ради того, чтобы сделать его «готовым» за один проход.

Полнота Inventory достигается исследованием исходного кода.

Рабочий объём для исполнителя определяется отдельно Project Manager.

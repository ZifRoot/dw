# AUD-019-02 — Инструкция Project Manager

## Цель

Преобразуй актуальный Inventory в небольшой, выполнимый план работы для исполнителя.

## Получай входные данные

Используй:

- `AUD-019-02-Shared-Test-Inventory.md`;
- решения эксперта, зафиксированные в Inventory;
- расхождения, обнаруженные исследователем;
- текущий статус уже запланированных задач.

## Выполни

1. Прочитай актуальный Inventory целиком в части незавершённых элементов.
2. Найди элементы без тестов и элементы с неполным покрытием.
3. Учти отдельный блок расхождений, обнаруженных исследователем.
4. Рассматривай исправление некорректного существующего теста как обычную рабочую задачу, если исследователь подтвердил расхождение.
5. Не исправляй Inventory вместо исследователя.
6. Не придумывай техническое решение там, где его должен определить эксперт.
7. Используй экспертные решения для оценки готовности задачи.
8. Оцени примерный объём работы.
9. Учитывай установленный лимит рабочего блока: время, объём контекста, токены или другую принятую в проекте единицу.
10. Не помещай в один пункт плана настолько большую задачу, что исполнитель не сможет качественно завершить её за один рабочий блок.
11. Разделяй крупную работу на несколько независимых последовательных задач.
12. Составляй план только на ближайший необходимый объём работы, а не на бесконечное заполнение Inventory.
13. Приоритизируй задачи глобально, сравнивая работу по всему shared.
14. Не углубляй бесконечно один хорошо покрытый метод, если есть другие элементы без базового теста.
15. Учитывай критичные failure/exception, существенные edge cases и расхождения исследователя.
16. При равной важности предпочитай задачу, которую проще полностью завершить и проверить в текущем рабочем блоке.
17. Запиши результат в отдельный план Project Manager.
18. После выполнения рабочего блока пересмотри план по обновлённому Inventory.

## Формат пункта плана

Каждый пункт должен содержать:

- приоритет;
- конкретный файл/элемент;
- конкретный сценарий;
- категорию;
- причину приоритета;
- оценку сложности или объёма;
- ожидаемый результат;
- краткое техническое решение или ссылку на решение эксперта;
- статус.

## Ограничение размера

Не пытайся перечислить весь Inventory в текущем плане.

План должен содержать только тот объём, который разумно передать исполнителю сейчас.

Если задача слишком большая, раздели её.

Если задача не готова технически, не передавай её исполнителю как READY.

## Реакция на расхождения

Если исследователь обнаружил:

> Inventory утверждает, что тест проверяет edge cases, но фактически тест проверяет только success.

Сделай следующее:

1. прочитай запись исследователя;
2. проверь, есть ли техническое решение эксперта;
3. оцени исправление как отдельную рабочую задачу;
4. включи её в план с подходящим приоритетом;
5. не удаляй исходную запись исследователя из Inventory.

## Результат

Project Manager должен оставить после себя короткий актуальный список задач, который исполнитель может брать по порядку.

Полнота Inventory не является критерием длины плана.

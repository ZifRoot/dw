# AUD-019-02 — Инструкция эксперта

## Цель

Определи, что именно необходимо проверить и как это корректно реализовать.

## Выполни

1. Изучи элементы Inventory, требующие анализа.
2. Для каждого элемента определи observable behavior.
3. Определи применимые категории:
   - success;
   - edge;
   - failure;
   - exception;
   - async;
   - state;
   - concurrency;
   - side-effect;
   - dependency.
4. Разделяй failure и exception.
5. Определи unit или integration.
6. Определи зависимости и необходимые test doubles.
7. Оцени сложность реализации.
8. Для сложных сценариев опиши конкретный способ реализации.
9. Если задача зависит от инфраструктуры, укажи её.
10. Если корректное тестирование невозможно без изменения production-кода, зафиксируй ограничение и предложи отдельную задачу на refactoring.
11. Проверь замечания исследователя в Inventory и определи технический способ их исправления.
12. Не назначай глобальный приоритет и не формируй рабочий объём — это задача Project Manager.
13. Обнови Inventory так, чтобы исполнитель мог понять требуемый сценарий без повторного проектирования.

## Результат

Для каждого подготовленного элемента Inventory должно быть понятно:

- что проверить;
- почему это является частью поведения;
- какой тест написать;
- какие зависимости нужны;
- насколько это сложно;
- какие ограничения существуют.
